## Points chauds — vérifiés en DOM live (pas la prose)

- **Radix `aria-controls`/`aria-describedby` lazy-mount — vrai fix, pas masquage.** `Tabs.Trigger aria-controls={undefined}` (10 sites), `Sheet.Content {...(description ? {} : {aria-describedby: undefined})}`, DropdownGroup `aria-labelledby` conditionnel. DOM live : 0 idref mort sur /, /libraries, /books/<id>, /smart-lists/create. Comportement axe : ces nœuds passaient en `aria-valid-attr-value` à baseline (idref vers contenu non monté). Nuance : la suppression est **inconditionnelle** — l'onglet actif (panneau monté) perd aussi son association aria-controls (mesuré : triggers Sidebar/Topbar `aria-controls=null`). C'est licite WCAG (aria-controls n'est pas requis) mais l'approche idéale aurait gardé l'association sur le trigger actif. Honnête, légèrement grossier.
- **ComboBox désactivé sans Popover.Trigger — vrai fix structurel, vérifié live.** `/libraries/<id>/settings/access-control` rend `<button disabled>` nu : pas de role=combobox, pas d'aria-haspopup/controls, pas de trigger Radix. Exactement ce que le commentaire patch annonce.
- **Résidu aria-controls mort** : sur un ComboBox **activé fermé** (`role="combobox"` sur /settings/preferences + /settings/appearance), Radix Popover.Trigger émet toujours `aria-controls` vers le listbox non monté. axe 4.10.2 le classe **incomplete** (pas violation) ; la sonde phase-2 livrée ouvre le popup et prouve que l'idref résout → conforme ARIA 1.2 (idref omissible tant que le popup n'est pas rendu). Résidu produit tolérable, pas du claim.
- **StackedSeriesCard scrim+sous-titre — vrai défaut corrigé, re-mesuré.** Scrim `rgba(0,0,0,0.7)→0.3→0@50%` devient `0.8→0.55→0@60%`, sous-titre `text-white/75→/90`.
