2. `scope-compare.json` : `final.scopeHash` contient `f6915c75` = le **statesHash** du scope.json (le vrai scopeHash final est `ca0ae73b`) — incohérent avec les lignes baseline/install qui portent leurs vrais scopeHash ; `detail.scenarios_final` listait encore 46 scénarios (sans les 5 états dark). *L'extension 45→50 elle-même est bien documentée ; seuls les champs de détail sont périmés/mis-étiquetés.*
3. `verify.mjs` asymétrie : la boucle d'attente du retour en clair n'a **pas** de fail-on-timeout (la boucle dark, elle, `ok(...)` à i==39) — si la restauration light échoue, le script sortirait vert sans avoir prouvé le retour. Non bloquant (prouvé live), mais l'assertion n'est pas symétrique.
4. `incomplete-probes.mjs` : la restauration passe par PUT config seul — `setTheme` s'applique live donc le thème servi redevient clair immédiatement (vérifié), mais le run laisse `configChanged` en file → un « Restart Needed » peut rester affiché ; sans effet sur les scans suivants (themed assets corrects).
5. Mon sweep dark a révélé que la restauration de thème par fetch côté page **peut échouer silencieusement** (PUT sans `credentials` explicite dans un contexte étrange : mon instance est restée dark après un premier sweep — REST PUT manuel requis). Le code des sondes est correct (même origine, cookies), mais le pattern « restaurer par PUT sans restart » dépend de `CommitConfiguration` → setTheme : à garder en tête si le produit change.
